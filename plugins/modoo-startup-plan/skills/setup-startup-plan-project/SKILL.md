# 사업계획서 프로젝트 만들기

## 절차

1. 아이디어의 고객과 사용상황을 먼저 확인한다. 아이디어 한 문장만 있으면 질문 하나만 하고 답을 받기 전에는 프로젝트를 생성하지 않는다.
2. 사용자가 원하는 프로젝트 경로, 프로그램명, 트랙, 작업 모드(DEMO / PARTIAL / REAL)를 확인한다. 트랙이 불명확하면 unknown, 작업 모드가 불명확하면 PARTIAL을 사용한다.
3. 이 SKILL.md가 있는 폴더를 스킬 루트로 정하고 그 아래 `scripts/create_project.py`를 실행한다. 프로젝트 루트의 scripts로 해석하지 않는다.

~~~powershell
python "<이 SKILL.md가 있는 폴더>\scripts\create_project.py" --path "C:\작업\창업_사업계획서" --track unknown --mode PARTIAL
~~~

4. 생성 결과를 확인하고 00. 시작하기/프로그램프로필.json, 프로젝트상태.md, 사전점검.md, 입력자료목록.csv, 실습범위카드.md를 읽는다.
5. 사용자가 말한 프로그램명·평가기준·배점은 프로그램프로필에 즉시 기록하고 `criteria_status`를 `USER_PROVIDED_UNVERIFIED`로 둔다. 공식 원문을 확인하면 출처와 함께 `OFFICIAL_VERIFIED`로 바꾼다. 다른 프로그램이면 `program_pack`은 generic으로 유지한다.
6. 사용자가 말한 아이템·고객·사용상황은 회사사실표의 F001 계열에 `사용자 제공·미검증`으로 기록한다. 최초 체크포인트를 전부 빈 템플릿으로 끝내지 않는다.
7. 사용자가 제공한 파일은 원본을 보존한 복사본만 해당 폴더에 두고 입력자료목록에 공개등급·마스킹·읽기 상태를 기록한다.
   - 회사·대표·아이템 자료: 01. 회사내용/공유가능 원본
   - 공고·평가표·작성요령: 02. 공고문 및 평가지표/원본
   - 제출 이후 수정 허용이 확인된 경우에만 원본 HWP: 03. 사업계획서양식/원본 HWP 보관
   - 같은 조건에서 한글로 저장한 작업용 HWPX: 03. 사업계획서양식/작업용 HWPX
8. REAL은 트랙, 목표 결과물, 공유 가능한 입력이 확인되지 않으면 다음 단계로 진행하지 않는다. 수정 가능 여부가 불명확하면 HWPX 단계만 건너뛴다.
9. Python이나 설치가 실패하면 빈 프로젝트 생성을 반복하지 말고 제공된 스타터 프로젝트로 전환한다.
10. 99. 원본백업은 수정하지 않는다.
11. 기존 파일은 `--force`를 사용해도 덮어쓰지 않는다. `PROTECTED_MODIFIED`가 나오면 사용자가 직접 비교하도록 보고한다.

폴더별 역할은 references/project-layout.md를 읽는다.
