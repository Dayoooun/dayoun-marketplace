# 모두의창업 사업계획 한바퀴

아래 단계를 순서대로 진행한다. 각 단계의 전용 스킬이 있으면 명시적으로 사용한다.

## 시작 전 확인

1. 제출물의 정확한 명칭, 마감일, 강의·멘토링 이후 수정 가능 여부를 확인한다.
2. 일반·기술트랙과 로컬트랙 중 해당 트랙을 확인한다.
3. 공유 가능한 자료만 사용한다. 개인정보, 고객명단, 계좌, 신분증, 비공개 계약서는 제거하거나 마스킹한다.
4. 회사 사실, 외부 근거, 가정, 향후 계획을 섞지 않는다.
5. 사용자가 제공하지 않은 실적·수치·계약·인증·특허를 만들지 않는다.

## 단계

1. 프로젝트 준비: $setup-startup-plan-project로 표준 폴더와 기본 파일을 만든다.
2. 자료 정리: 회사자료는 01. 회사내용, 공고와 평가기준은 02. 공고문 및 평가지표, 원본 HWP와 작업용 HWPX는 03. 사업계획서양식에 둔다.
3. 근거 조사: $research-startup-evidence로 고객·시장·경쟁대안 근거와 증거원장을 만든다.
4. 초안 구성: $draft-modoo-plan으로 실제 양식과 평가기준에 맞춘 핵심 항목 초안을 만든다.
5. 검토: $review-modoo-plan으로 PASS/WARN/BLOCK 검토를 수행한다. BLOCK이 남으면 HWPX 반영 전에 수정한다.
6. HWPX 반영: $fill-hwpx-template로 중괄호 항목을 스캔하고 원본이 아닌 새 HWPX 파일을 만든다.
7. 최종 확인: HWPX 구조 검증과 미치환 항목 검사를 수행하고, 가능하면 한글에서 직접 열어 육안 확인한다.

각 단계가 끝날 때 00. 시작하기/프로젝트상태.md에 완료 항목, 남은 확인사항, 다음 행동을 기록한다.

## 종료 조건

- 출처 없는 정량 주장이 없다.
- 회사의 현재 사실과 향후 계획이 구분되어 있다.
- 평가기준과 초안 항목의 연결을 추적할 수 있다.
- 미치환 중괄호와 BLOCK 항목이 없다.
- 원본 파일은 보존되어 있다.
- 한글에서 정상 열기 전에는 제출 가능하다고 단정하지 않는다.

세부 파일 흐름은 references/workflow.md를 읽는다.
