# 평가기준형 사업계획 초안

## 사전 조건

- 입력자료목록.csv에서 필요한 입력이 읽기 가능하고 공유 가능한 상태여야 한다.
- 실습범위카드에서 작업 모드와 대상 양식 항목을 확정해야 한다.
- 회사사실표에서 사실·가정·계획이 구분되어 있어야 한다.
- 증거원장에 사용할 수 있는 근거가 있어야 한다.
- 요구사항추적표.csv에서 평가기준, 양식 필드, 플레이스홀더가 연결되어 있어야 한다.
- 프로그램프로필에 기록된 실제 양식과 평가기준이 일반 참조보다 우선한다.

## 절차

1. 실제 양식의 항목과 평가기준을 대응시킨다.
2. 공식 배점이 공개되지 않았으면 임의 점수를 공식 배점처럼 쓰지 않는다.
3. 문제 → 목표고객 → 기존대안의 한계 → 해결책 → 차별성 → 기대효과 → 시장성 → 구현·검증계획 순으로 논리를 연결한다.
4. 회사 내부 입력은 회사사실표의 F001 형식 fact_id로 연결하고, 외부·고객 근거로 검증하는 주장은 C001 형식 claim_id로 연결한다. 2시간 실습의 핵심 주장은 C001 하나로 고정한다.
5. 근거가 없으면 자연스럽게 꾸미지 말고 {확인필요: 항목}으로 남긴다.
6. 현재 보유 역량과 향후 계획을 같은 시제로 쓰지 않는다.
7. 05. 작성초안/핵심초안.md에 초안을 저장한다.
8. 각 문단의 criterion_id, form_field_id, claim_ids, draft_file을 요구사항추적표.csv에 기록한다.
9. HWPX 스캔으로 확보한 플레이스홀더만 03. 사업계획서양식/placeholder-values.draft.json에 채운다. 필드명을 추측해 새로 만들지 않는다.
10. 05. 작성초안/content-lock.md의 승인상태를 NOT_APPROVED로 유지하고 콘텐츠 검토를 요청한다.

## 승인 경계

- 이 스킬은 placeholder-values.approved.json을 채우지 않는다.
- review-modoo-plan의 content 단계가 RUN_COMPLETE, 필수항목 100%, 근거 커버리지 100%, BLOCK 0을 기록한 뒤 사용자가 문안을 명시적으로 승인해야 한다.
- 승인 시 content-lock.md에 승인자·승인일시·초안 버전을 기록하고 검토된 값만 approved JSON으로 복사한다.
- 승인 이후 초안이 바뀌면 기존 승인을 무효화하고 콘텐츠 검토부터 다시 수행한다.

공통 평가 정렬은 references/evaluation-map.md를 읽는다. 프로그램프로필의 `program_pack`이 `pnu-modoo`이고 사용자가 현재 공식 자료를 제공했을 때만 references/pnu-modoo-program-pack.md를 추가로 읽는다.
