# 콘텐츠와 HWPX 산출물 2단계 검토

검토 단계를 지정하지 않으면 사용 가능한 입력을 보고 `content` 또는 `hwpx-output`을 먼저 선언한다. 두 단계를 한 번에 통과한 것으로 처리하지 않는다.

## 콘텐츠 검토 범위

검토를 시작하기 전에 다음 중 하나를 선언하고 콘텐츠검토.md에 분모를 적는다.

- EDUCATION_SINGLE_CLAIM: 공백 1개, C001 1개, 변화결정 1개, 다음 행동과 1분 IR만 검토한다.
- SELECTED_SECTION: 실습범위카드에서 선택한 양식 항목과 그 항목에 연결된 F/C ID만 검토한다.
- FULL_DOCUMENT: 공식 양식 전체와 제출 대상 문서의 모든 필수항목·사실 주장을 검토한다.

범위 밖 항목은 누락으로 숨기지 말고 NOT_REVIEWED로 기록한다. `100%`는 반드시 `범위 내 4/4, 100%`처럼 분자와 분모를 함께 쓴다. 범위가 다른 결과끼리 100%를 같은 의미로 비교하지 않는다.

## 1단계 · content

### 필수 입력

- 00. 시작하기/입력자료목록.csv
- 00. 시작하기/실습범위카드.md
- 00. 시작하기/요구사항추적표.csv
- 프로그램프로필, 회사사실표와 공고·평가기준 원문
- 공백진단표, 증거원장, 검증활동기록, 멘토링변화기록, 다음공식마감실행카드
- 핵심초안이 있으면 해당 초안

HWPX 선택 트랙을 사용할 때만 template-field-map.csv와 placeholder-values.draft.json을 추가로 검토한다.

### 검토

1. 선언한 검토 범위와 범위 내 필수항목·사실 주장 분모를 먼저 확정한다.
2. 필수 활동 결과물과 평가기준이 요구사항추적표에서 연결됐는지 확인한다.
3. 공백 1개, C001 근거 1개, 유지·수정·보류 결정, 다음 행동과 1분 IR이 같은 근거 흐름으로 연결됐는지 확인한다.
4. 회사 내부 입력은 F001 계열, 외부·고객 근거로 검증하는 범위 내 사실·수치·분석 주장은 C001 계열과 연결됐는지 확인한다.
5. 실적·매출·고객·계약·특허·인증을 근거 없이 단정하면 BLOCK 처리한다.
6. 정량 주장에 출처·기준일·단위가 없거나 사실과 계획이 섞이면 BLOCK 처리한다.
7. 글자·페이지 제한, 개인정보·비공개정보, 장문 복사, 과장 표현을 검토한다.
8. 범위 내 필수항목 커버리지와 범위 내 사실 주장 근거 커버리지를 분자/분모와 함께 기록한다.

### 출력과 통과 기준

06. 검토결과/콘텐츠검토.md에 검토상태, 검토 범위, 대상 버전, 시각, 범위 내 분모와 커버리지, NOT_REVIEWED, PASS/WARN/BLOCK, 수정 목록을 기록한다.

다음을 모두 만족해야 콘텐츠 검토를 통과한다.

- 검토상태가 RUN_COMPLETE이다.
- 범위 내 필수항목 커버리지가 분모와 함께 100%이다.
- 범위 내 사실 주장 근거 커버리지가 분모와 함께 100%이다.
- BLOCK이 0건이다.
- `{확인필요}`가 없거나 사용자가 의도적 제외를 승인했다.

EDUCATION_SINGLE_CLAIM 또는 SELECTED_SECTION 통과를 전체 제출본 통과로 표현하지 않는다. 통과 후에도 자동 승인하지 않는다. 사용자가 문안을 명시적으로 승인하면 05. 작성초안/content-lock.md에 승인자·승인일시·초안버전을 기록한다. HWPX 선택 트랙에서는 승인된 문안만 placeholder-values.approved.json에 복사한다.

## 2단계 · hwpx-output

### 필수 입력

- 통과한 06. 검토결과/콘텐츠검토.md
- 승인된 03. 사업계획서양식/placeholder-values.approved.json
- template-field-map.csv와 요구사항추적표.csv
- 생성된 HWPX와 replacement-log.csv
- HWPX 구조검증 결과

### 검토

1. content-lock의 승인 대상 초안과 치환값이 일치하는지 확인한다.
2. 치환 대상·횟수·누락 항목이 template-field-map.csv와 일치하는지 확인한다.
3. 미치환 플레이스홀더, NOT_FOUND, SKIPPED_EMPTY, 구조검증 실패를 BLOCK 처리한다.
4. 한글에서 표, 줄바꿈, 글자 겹침, 페이지 넘김을 확인하고 검수자·시각·대상 파일을 기록한다.

06. 검토결과/산출물검토.md에 결과를 기록한다. 구조검증과 육안검수가 모두 완료되고 BLOCK이 0건일 때만 FULL로 판정한다.

## 완료 수준

- FULL: 승인 문안 치환, 콘텐츠 검토, 구조검증, 산출물 검토, 한글 육안검수를 모두 완료했다.
- DRY_RUN: 콘텐츠 승인과 수동 치환표까지 완료했지만 HWPX 생성 또는 육안검수를 완료하지 않았다.
- FALLBACK: Markdown 초안과 수동 반영표만 완료했다.

07. 최종본/release-manifest.md에 완료 수준과 각 검토상태를 기록한다. NOT_RUN을 BLOCK 0으로 해석하거나 FULL이 아닌 결과를 제출 가능이라고 말하지 않는다. 세부 체크표는 references/review-rubric.md를 읽는다.
