# 사업계획서 프로젝트 준비

## 시작 조건

고객·사용 상황·문제에 대한 최소 정보가 없으면 질문 하나를 먼저 하고 답을 받기 전에는 폴더를 만들지 않는다. 사용자가 이미 제공한 답은 그대로 기록한다.

## 파이프라인 위치: 1단계 입력 보존 + 2단계 사업정보 분석

이 스킬은 공고문·평가지표·작성지침·양식과 회사·사업·아이디어 원본을 안전하게
정리한다. 사업계획서 문장을 작성하거나 시장조사를 시작하는 단계가 아니다.

**완료 조건**: 공식 원문과 작업 사본이 구분되고, 사업정보가 `확인된 사실 /
사용자 제공·미확인 / 가정 / 앞으로 할 계획`으로 나뉘며, 누락 자료가 기록돼야 한다.

**다음 단계**: `complete-business-plan`이 공고 요구사항과 사업정보를 비교해
부족한 근거와 확인 질문을 만들고, 그 질문만 `research-business-evidence`에 넘긴다.

## 강제 프로젝트 구조

입력자료가 있는 참고 폴더에는 파일이나 하위 폴더를 만들지 않는다. 참고 폴더는 읽기
전용으로 두고 별도의 프로젝트 루트에 아래 최상위 구조를 정확히 만든다.

```text
00. 시작하기
01. 사업정보
02. 목적 및 요구사항
03. 사업계획서양식
04. 조사자료
05. 작성초안
06. 검토결과
07. 최종본
08. 발표덱
99. 원본백업
```

에이전트가 임의 이름으로 최상위 폴더를 바꾸거나 생략하면 BLOCK이다. 원본은
`99. 원본백업`과 각 원본 하위 폴더에 복사하고 작업용 파일과 분리한다.

## 상호작용 모드

- `DEMO`: 검증·강의시연용이다. 에이전트가 확인된 자료와 명시한 가정으로 1~6단계를 진행할 수 있지만 사용자 승인, 인터뷰, 견적, 실제 시험 결과를 만들어내지 않는다. 7단계는 검토 결과를 `BLOCK`으로 기록하고 8~10단계로 넘어가지 않는다.
- `REAL`: 실제 신청서용이다. 에이전트가 혼자 방향을 확정하지 않는다. 1~2단계 분석 뒤 우선 질문을 사용자와 확인하고, 5단계 전략 대안을 함께 선택하며, 7단계 문안을 사용자가 승인한 뒤에만 HWPX·PPT로 넘어간다.
- `PARTIAL`: 일부 자료 정리·일부 장절 작업용이며 완료본이나 승인본으로 표시하지 않는다.

REAL 모드의 질문 답변·전략 선택·문안 승인·HWPX/PPT 선택은
`00. 시작하기/사용자협업상태.json`에 사용자 원문 인용과 확인 시각을 기록한다.
에이전트가 추론한 답을 사용자 답변으로 기록하면 BLOCK이다. `advance_stage.py`가
3·5·7·8·10단계에서 이 기록을 검사한다.
PASS/BLOCK evidence는 해당 단계의 산출 폴더 안에 있는 실제 파일이어야 한다.
디렉터리, 다른 단계 파일, 앞 단계에서 이미 사용한 파일은 BLOCK이다. 최상위 폴더는
필수 10개와 명시한 숨김 메타데이터 폴더 외에 추가할 수 없다.

## 절차

1. 사용 목적을 `지원사업`, `투자·IR`, `사내 검토`, `대출·제안`, `교육`, `기타` 중 하나로 정한다. 모르면 `기타`로 만들지 말고 `unknown`으로 둔다.
2. 이 SKILL.md가 있는 폴더를 스킬 루트로 정하고 `scripts/create_project.py`를 실행한다. 프로젝트 루트의 scripts로 해석하지 않는다.
3. Windows에서는 `python`, macOS/Linux에서는 `python3`를 사용한다.

Windows 예시:

```powershell
python "<이 SKILL.md가 있는 폴더>\scripts\create_project.py" --path "사업계획서_프로젝트" --purpose "지원사업" --mode PARTIAL
```

macOS/Linux 예시:

```bash
python3 "<이 SKILL.md가 있는 폴더>/scripts/create_project.py" --path "사업계획서_프로젝트" --purpose "지원사업" --mode PARTIAL
```

4. 사용자가 제공한 회사·팀·제품·고객·사용 상황은 `01. 사업정보/사업정보표.md`에 `사용자 제공·미확인` 상태로 기록한다. 전부 빈 템플릿으로 끝내지 않는다.
5. 공식 공고, 평가표, 양식이 있으면 원본을 복사해 `02. 목적 및 요구사항/원본`과 `03. 사업계획서양식/원본`에 둔다. 원본을 직접 수정하지 않는다.
6. 외부 공유가 가능한 자료인지 확인하고 개인정보, 고객명단, 계좌, 신분증, 비공개 계약 정보는 제거하거나 가린다.
7. 기존 파일이 있으면 덮어쓰지 않는다. `--force`도 사용자가 수정한 파일을 보호하고 목록으로 알리는 용도다.
8. 생성 후 `00. 시작하기/프로젝트상태.md`에 완료된 단계, 누락 자료, 다음 행동을 기록한다.

9. `scripts/advance_stage.py check "사업계획서_프로젝트"`로 강제 구조와 10단계 상태를 확인한다.
10. 각 단계는 `start`로 시작하고 산출물 파일을 만든 뒤 `complete --status PASS --evidence <상대경로>`로 완료한다. 앞 단계가 PASS 또는 선택 단계의 NOT_REQUESTED가 아니면 다음 단계로 넘어가지 않는다.

Windows 예시:

```powershell
python "<이 SKILL.md가 있는 폴더>\scripts\advance_stage.py" start "사업계획서_프로젝트" 1
python "<이 SKILL.md가 있는 폴더>\scripts\advance_stage.py" complete "사업계획서_프로젝트" 1 --status PASS --evidence "02. 목적 및 요구사항/목적과요구사항.md"
```

macOS/Linux에서는 `python3`와 `/` 경로 구분자를 사용한다. 1~7단계는 필수라
NOT_REQUESTED로 건너뛸 수 없다. 8~10단계는 사용자가 선택하지 않았을 때만
NOT_REQUESTED로 닫는다. PASS에는 프로젝트 안에 실제로 존재하는 evidence가 필요하다.

폴더와 파일의 역할은 `references/project-layout.md`를 읽는다.
