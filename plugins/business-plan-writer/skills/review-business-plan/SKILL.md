# 사업계획서 검토

검토를 시작할 때 범위를 먼저 선언한다.

- QUICK: 가장 중요한 보완점과 관련 문장만 검토
- SECTION: 선택한 장·절 전체를 검토
- FULL: 목적에 필요한 전체 문서와 필수 요구사항을 검토

범위 밖 항목은 `NOT_REVIEWED`로 남긴다. 일부만 검토한 결과를 전체 문서 완료로 표현하지 않는다.

## 파이프라인 위치: 7단계 문안 승인 + 선택 산출물 검증

내용 검토는 HWPX·PPT 생성보다 먼저 한다. BLOCK을 해결하고 사용자가 최종 canonical
문안과 공개 범위를 승인해야 선택 산출물을 만들 수 있다.

HWPX를 선택한 경우 승인 문안 일치, 미치환·빈 값, ZIP/XML 구조, 시각자료의 의미상 위치·참조 무결성·원본 쪽 설정, 한글 화면을 검증한다.
PPT를 선택한 경우 HWPX와 무관하게 승인 payload·deck brief·visible-text manifest를
고정하고 mode 자동검사, fact·structure·contract 세 검증자, PPTX/PDF 화면을 검증한다.

**다음 단계**: 문안 승인 뒤 사용자가 선택한 HWPX와 PPT를 각각 독립적으로 실행한다.

## 1단계: 내용 검토

1. 문서의 목적, 독자, 기준 문서, 검토 대상 파일과 버전을 기록한다.
2. 공식 요구사항이 있으면 필수 항목과 초안 위치가 연결되는지 확인한다.
3. 문제·고객·해결책·차별점·시장·수익·실행·팀·재무·위험이 필요한 범위 안에서 이어지는지 본다.
4. 사용자가 제공한 정보, 외부에서 확인한 사실, 가정, 앞으로 할 계획이 구분되는지 확인한다.
5. 숫자, 날짜, 고유명사, 단위가 문서 전체에서 같은지 확인한다.
6. 외부 사실과 수치에 출처, 기준일, 적용 범위가 있는지 확인한다.
7. “최초·유일·1위·확실” 같은 과장 표현과 근거 없는 고객 반응·실적을 찾는다.
8. 개인정보, 고객명단, 계좌, 신분증, 비공개 계약 정보가 포함됐는지 확인한다.
9. 각 문제를 PASS, WARN, BLOCK, NOT_REVIEWED로 표시하고 이유와 수정안을 쓴다.

### 상태 의미

- PASS: 선언한 범위에서 기준을 충족함. 외부 기관의 합격이나 승인을 뜻하지 않음
- WARN: 사용할 수 있으나 확인 또는 표현 완화가 필요함
- BLOCK: 허위 가능성, 필수 요구 누락, 수치 충돌, 개인정보처럼 다음 단계 전에 고쳐야 함
- NOT_REVIEWED: 이번 범위에서 확인하지 않음

검토 범위 안의 필수 항목 수와 확인 필요한 문장 수를 먼저 적고, 각각 몇 건을 확인했는지 기록한다. 분모가 다른 비율을 같은 완성도로 비교하지 않는다.

## 2단계: 문체와 서식 검토

`../draft-business-plan/references/writing-style.md`를 읽고 작성 단계와 같은 기준을 적용한다. 최신 공식 양식이 있으면 공통 기본값보다 우선한다.
HWPX 시각자료가 있으면 `../fill-hwpx-template/references/visual-design-system.md`를 필수로 읽는다.

1. `~한다`와 `~합니다` 같은 종결 문체가 혼용됐는지 확인한다.
2. 한 문단에 하나의 핵심이 있고 첫 문장에 답이 드러나는지 확인한다.
3. 장·절·항목의 번호 체계가 중간에 바뀌거나 누락되지 않았는지 확인한다.
4. 공백·탭으로 들여쓰기를 만들지 않았고 같은 목록 단계의 정렬이 같은지 확인한다.
5. 표의 제목, 머릿글, 단위, 기준일, 출처가 명확하고 같은 열의 표기가 일관되는지 확인한다.
6. 양식 제한을 넘는 긴 문장, 불필요한 줄 바꿈, 표 안의 과도한 서술을 줄인다.

의미 전달을 방해하거나 공식 형식을 어긴 서식 문제는 BLOCK, 단순한 표기 불일치는 WARN으로 표시한다.

## 3단계: 사용자 승인

BLOCK을 처리한 뒤에도 자동으로 최종본을 만들지 않는다. 사용자가 최종 표현과 공개 범위를 확인하면 `06. 검토결과/문안승인.md`에 대상 파일, 버전, 승인자, 일시를 기록한다.

초안이 바뀌면 이전 승인을 무효로 하고 다시 검토한다.

## 4단계: HWPX 결과 검토

HWPX를 만들었을 때만 실행한다.

1. 승인한 문안과 실제 치환값이 같은지 확인한다.
2. 미치환 항목, 빈 값, 잘못된 위치를 BLOCK으로 처리한다.
3. HWPX ZIP·XML 구조검사를 통과했는지 확인한다.
4. 시각자료가 승인된 `앞 문단 / 뒤 문단` 사이에 있고 답변 셀 마지막으로 밀리지 않았는지 확인한다.
5. 시각자료가 `tc → subList → p → run → tbl` 계층의 1열 2행 중첩표인지 확인한다.
6. 캡션이 `그림 N. 핵심 그림명` 형식으로 짧고 가운데 정렬됐는지 확인한다.
7. `<img binaryItemIDRef>`·manifest·`BinData` 파일이 일치하는지 확인한다.
8. 원본과 결과의 `secPr` canonical digest가 같아 쪽 크기·여백·테두리가 보존됐는지 확인한다.
9. 한글에서 실제 문맥 위치, 이미지 비율·해상도, 표, 줄바꿈, 글자 겹침, 페이지 넘김을 화면으로 확인한다.
10. 자동 구조검사와 한글 화면 확인이 모두 끝나기 전에는 최종 제출 준비 완료라고 말하지 않는다.

세부 질문은 `references/review-rubric.md`를 읽는다.
