# 사업계획서 처음부터 끝까지

사용자가 가진 자료와 목적에 맞춰 필요한 만큼만 진행한다. 복잡한 내부 관리번호보다 쉬운 말을 먼저 사용한다.

## 먼저 하나만 묻기

사업 아이디어의 **고객·사용 상황·문제**가 비어 있으면 다음 질문 하나만 하고 답을 기다린다.

> 누가, 어떤 상황에서, 어떤 문제를 해결하기 위해 이 사업을 이용하나요? 아직 모르면 모른다고 적어 주세요.

답을 받은 뒤 목적과 자료 상태를 확인한다. 사용자가 이미 말한 내용은 다시 묻지 않는다.

## 지원하는 작업

- 새로 작성: 아이디어와 자료에서 사업계획서의 뼈대와 초안을 만든다.
- 기존 문서 보완: 현재 문서에서 빠졌거나 약한 내용을 찾아 고친다.
- 공고·평가기준 맞춤: 사용자가 제공한 최신 공식 공고, 평가표, 양식을 우선 적용한다.
- 자율 사업계획: 공고가 없으면 독자, 의사결정 목적, 필요한 장·절을 먼저 정한다.

지원사업 신청, 투자·IR, 사내 검토, 대출·제안, 교육 실습 등 용도를 구분한다. 특정 기관의 기준을 기본값으로 가정하지 않는다.

## 쉬운 기본 흐름

1. **목적 정하기**: 누가 읽고 무엇을 결정하는 문서인지 확인한다.
2. **자료 정리하기**: `setup-business-plan-project`로 원본, 사업 정보, 요구사항, 조사자료, 초안, 최종본을 나눈다.
3. **부족한 내용 찾기**: 공식 기준이 있으면 그 기준으로, 없으면 일반 사업계획 기준으로 가장 중요한 보완점부터 찾는다.
4. **근거 확인하기**: `research-business-evidence`로 숫자·시장·고객·경쟁 관련 내용을 믿을 만한 자료에서 확인한다.
5. **초안 만들기**: `draft-business-plan`으로 확인된 정보와 아직 확인이 필요한 내용을 구분해 쓴다.
6. **검토하고 승인하기**: `review-business-plan`으로 누락, 앞뒤 불일치, 근거 없는 표현, 과장을 점검하고 사용자가 문안을 승인한다.
7. **다음 행동 정하기**: 담당자, 기한, 완료 기준이 있는 실행 항목을 만든다.
8. **양식에 반영하기**: 사용자가 원하고 수정 가능한 HWPX 복사본이 준비된 경우에만 `fill-hwpx-template`을 사용한다.

## 정보 구분

- **내가 알고 있는 정보**: 사용자가 제공한 회사, 팀, 제품, 고객, 실적 정보다. 출처나 확인 상태를 함께 적는다.
- **확인이 필요한 내용**: 시장 규모, 고객 반응, 경쟁 비교처럼 조사나 고객 기록으로 확인해야 할 내용이다.
- **앞으로 할 계획**: 아직 일어나지 않은 일정, 매출, 채용, 개발 계획이다. 현재 실적처럼 쓰지 않는다.

내부 파일에서는 추적을 위해 번호를 붙일 수 있지만, 초보자 안내에는 번호보다 위의 쉬운 이름을 사용한다.

## 완료 기준

작업 시작 시 아래 중 범위를 선언하고, 범위 밖은 완료로 표시하지 않는다.

- QUICK: 가장 중요한 보완점 1개와 근거 1개, 수정안 1개, 다음 행동 1개
- SECTION: 사용자가 선택한 장·절 전체
- FULL: 목적에 필요한 전체 문서와 필수 요구사항

항상 다음을 지킨다.

- 사용자가 주지 않은 실적, 수치, 고객 반응, 계약, 인증을 만들지 않는다.
- 공식 배점이나 요구사항이 없으면 임의 기준을 공식 기준처럼 말하지 않는다.
- 출처의 발표일, 기준연도, 단위, 적용 범위를 함께 기록한다.
- 원본은 보존하고 초안과 최종본을 구분한다.
- 개인정보와 비공개 자료는 제거하거나 가린다.
- HWPX 구조검사와 한글 화면 확인을 둘 다 통과하기 전에는 제출 준비 완료라고 말하지 않는다.

세부 단계와 산출물은 `references/workflow.md`를 읽는다.
