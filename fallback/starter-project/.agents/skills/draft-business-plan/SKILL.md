# 근거가 보이는 사업계획서 초안

## 작성 전에 확인

- 문서의 독자와 의사결정 목적
- 공식 공고·평가표·양식 유무
- 작업 범위: QUICK / SECTION / FULL
- 사용 가능한 사업 정보와 조사 근거
- 글자 수, 페이지 수, 파일 형식 같은 제한
- 공식 양식 또는 승인된 예시에서 확인한 문체·번호·들여쓰기·표 기준

공식 요구사항이 있으면 그 문구와 순서를 우선한다. 없으면 `references/evaluation-map.md`의 공통 관점을 질문 목록으로만 사용한다.
문안을 작성하기 전에 `references/writing-style.md`를 읽고, 공식 양식이 있으면 그 기준을 우선해 문체와 서식을 정한다.

## 작성 절차

1. 필요한 장·절과 각 장이 답해야 할 질문을 먼저 정한다.
2. `문제와 고객 → 해결책과 차별점 → 시장과 수익 구조 → 실행계획과 팀 → 비용·재원·성과지표 → 위험과 다음 검증`의 연결을 확인한다.
3. 사용자가 제공한 정보, 외부에서 확인한 근거, 앞으로 할 계획을 구분한다.
4. 숫자와 외부 사실에는 출처 또는 근거 위치를 연결한다.
5. 근거가 없으면 자연스럽게 꾸미지 말고 `{확인필요: 항목}`으로 남긴다.
6. 현재 실적과 목표 수치, 보유 자원과 향후 확보 계획을 같은 시제로 쓰지 않는다.
7. 각 장의 첫 문장은 핵심 답을 먼저 제시하고, 그 뒤에 근거와 실행 방법을 붙인다.
8. 기존 문서를 보완할 때는 원문을 보존하고 `이전 내용 / 확인한 정보 / 수정안 / 이유`를 변경기록에 남긴다.
9. 초안은 `05. 작성초안/사업계획서초안.md`에 저장하고 사용자의 승인을 받기 전에는 최종본으로 표시하지 않는다.
10. HWPX용 값은 실제 양식의 확인된 플레이스홀더만 사용하고, 먼저 draft JSON에 둔다.
11. 문안 전체에 같은 문체, 장·절 번호 체계, 목록 단계, 들여쓰기와 표 단위를 적용한다.

## 목적별 조정

- 지원사업·공모: 최신 공식 공고, 평가표, 작성요령, 양식 순서를 따른다.
- 투자·IR: 시장, 성장 방식, 팀, 실적, 자금 사용과 다음 이정표를 선명하게 연결한다.
- 사내 검토: 전략 적합성, 자원, 일정, 비용·효과, 위험과 의사결정 항목을 강조한다.
- 대출·제안: 수행·상환 가능성, 계약 조건, 현금흐름과 증빙을 우선한다.
- 자율 문서: 독자와 결정 목적에 필요하지 않은 장은 억지로 추가하지 않는다.

특정 프로그램 참고자료는 사용자가 해당 프로그램의 최신 공식 원문을 제공했을 때만 `references/program-profiles/`에서 골라 읽는다. 참고자료보다 사용자가 제공한 최신 원문이 항상 우선한다.
