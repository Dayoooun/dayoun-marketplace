# 모두의창업 사업계획 한바퀴

아래 단계를 순서대로 진행한다. 각 단계의 전용 스킬이 있으면 명시적으로 사용한다.

## 시작 전 확인

1. 제출물의 정확한 명칭, 마감일, 강의·멘토링 이후 수정 가능 여부를 확인한다. 수정 가능 여부가 불명확하면 제출본은 읽기 전용으로 보존하고 고도화본·활동기록·실행계획만 만든다.
2. 일반·기술트랙과 로컬트랙 중 해당 트랙을 확인한다.
3. 공유 가능한 자료만 사용한다. 개인정보, 고객명단, 계좌, 신분증, 비공개 계약서는 제거하거나 마스킹한다.
4. 회사 사실, 외부 근거, 가정, 향후 계획을 섞지 않는다.
5. 사용자가 제공하지 않은 실적·수치·계약·인증·특허를 만들지 않는다.

## 작업 모드

- DEMO: 가상 회사자료와 강사가 준비한 주석 HWPX만 사용한다.
- PARTIAL: 개인자료 중 공유 가능한 일부와 실습범위카드에서 선택한 한 항목만 사용한다.
- REAL: 실제 자료를 사용한다. 입력자료목록·마스킹·제출물·트랙·수정 가능 여부가 확인되지 않으면 다음 단계로 진행하지 않는다.

## 기본 완료 기준

교육·멘토링 기본 경로는 다음 네 파일이 있으면 완료한다.

1. 02. 공고문 및 평가지표/공백진단표.md
2. 04. 시장조사 리서치/검증활동기록.md
3. 06. 검토결과/멘토링변화기록.md
4. 07. 최종본/다음공식마감실행카드.md

HWPX는 기본 완료 기준이 아니다. 제출 이후 수정 허용, 실제 양식 수령, 복사본 사전 검증이 모두 확인된 경우에만 선택 경로로 수행한다.

## 단계

1. 준비·사전점검: $setup-startup-plan-project로 표준 폴더와 기본 파일을 만들고 Green / Yellow / Red 실습 경로와 DEMO / PARTIAL / REAL 작업 모드를 정한다.
2. 자료·요구사항 정리: 입력자료목록, 실습범위카드, 회사사실표, 공고·평가기준, 양식 필드와 요구사항추적표를 작성한다.
3. 공백 진단: 평가기준 중 가장 중요한 공백 하나와 확인 질문을 공백진단표에 기록한다.
4. 근거 조사: $research-startup-evidence로 선택한 핵심 주장 하나에 공식 출처 또는 기존 고객 근거 하나를 연결하고 검증활동기록을 만든다.
5. 변화 기록: 제출 당시 생각과 새 근거를 비교해 유지·수정·보류 결정과 이유를 멘토링변화기록에 남긴다.
6. 다음 행동: 다음 공식 마감까지의 행동·담당·기한·완료 증거와 1분 IR을 실행카드에 작성한다.
7. 콘텐츠 검토·승인: $review-modoo-plan의 content 단계로 PASS/WARN/BLOCK/NOT_RUN을 확인하고 사용자가 최종 표현을 승인한다.
8. 조건부 HWPX: 허용 조건이 확인된 경우에만 $draft-modoo-plan과 $fill-hwpx-template로 승인값을 복사본에 반영한다. 플레이스홀더가 없으면 MANUAL_MAPPING으로 전환한다.
9. 조건부 산출물 검토: HWPX를 만들었을 때만 $review-modoo-plan의 hwpx-output 단계에서 구조·치환로그·한글 육안검수를 확인한다.

각 단계가 끝날 때 00. 시작하기/프로젝트상태.md에 완료 항목, 남은 확인사항, 다음 행동을 기록한다.

## 완료 수준

- FULL: 승인 문안 치환, 콘텐츠 검토, 구조검증, 산출물 검토, 한글 육안검수를 모두 완료했다.
- DRY_RUN: 승인 문안과 수동 치환표까지 완료했지만 개인 HWPX 또는 육안검수를 완료하지 않았다.
- FALLBACK: Markdown 초안과 수동 반영표만 완료했다.

NOT_RUN을 BLOCK 0으로 해석하지 않는다. 원본 제출본은 보존하며, 한글 육안검수와 운영기관 확인 전에는 제출 가능하다고 단정하지 않는다.

세부 파일 흐름은 references/workflow.md를 읽는다.
