# 참가자 한 장 빠른 시작

## 오늘 만드는 네 가지

1. 평가 공백 한 개
2. 근거·고객검증 기록 한 건
3. 유지·수정·보류 변화기록 한 건
4. 다음 공식 마감 실행카드와 1분 설명

제출본 원본은 수정하지 않습니다. `제출본_원본`, `수업_작업본`, `활동_결과물`을 서로 다른 파일로 보관합니다.

## 내 실습 경로

- Green: Codex·Python·웹·한글 사용 가능 → 개인자료와 파일형 확장
- Yellow: GPT 또는 Codex 사용 가능, 일부 자료·기능 부족 → 스타터 프로젝트와 오프라인 근거팩
- Red: 도구·사용량 문제 → 짝 실습과 완성 예시 검토

## GPT·Gemini·Claude 공통 요청 1 · 공백 진단

```text
아래 제출본 일부와 부산대 평가기준을 비교해줘.
이미 잘된 점을 늘어놓지 말고, 다음 단계에서 가장 먼저 확인할 공백 1개만 골라줘.
공식 문서에 없는 배점은 만들지 말고 다음 표로 작성해줘.

평가기준 | 현재 문장 | 부족한 근거 | 확인 질문 | 다음 행동
```

## 공통 요청 2 · 근거 기록

```text
선택한 주장 1개와 제공된 출처를 검토해줘.
출처가 실제로 말하는 범위를 넘겨 해석하지 말고 다음 형식으로 정리해줘.

주장 ID(C001) | 출처·기준일 | 확인한 내용 | 말할 수 없는 범위 | 유지·수정·보류 | 다음 검증
```

## 공통 요청 3 · 변화기록

```text
제출 당시 생각과 새 근거·멘토 의견을 비교해줘.
결론을 대신 정하지 말고 선택지와 이유를 보여줘.

변경 전 | 새 근거·피드백 | 유지·수정·보류 | 결정 이유 | 다음 검증
```

## 공통 요청 4 · 실행카드와 1분 설명

```text
다음 공식 마감까지 실행할 행동 1개를 정리해줘.
담당자, 기한, 완료 기준, 남길 증빙을 포함해줘.
이어서 문제–고객–해결–차별성–다음 검증 순서의 1분 설명 초안을 만들어줘.
확인되지 않은 실적과 시장 수치는 새로 만들지 마.
```

## Codex 확장

```text

```
