# PPT 한국어 산문 윤문 규칙

이 규칙은 scene-deck과 image-first, 신규 제작과 리디자인, 본문과 발표 대본·예상 Q&A에 모두 적용한다.

## 보호 대상

윤문 전에 다음 문자열을 그대로 추출해 보호 목록을 만든다.

- 숫자, 백분율, 통화, 날짜, 기간, 단위
- 회사명, 제품명, 기관명, 법령명, 논문·특허·R&D 과제명
- URL, 이메일, 파일 경로, 명령, 코드, 복사용 프롬프트
- 승인된 인용문, 출처 표기, `[E/U/H/P### | 출처·상태]`

윤문 뒤 보호 목록의 값과 출현 횟수가 달라지면 BLOCK한다. 어색함을 고치기 위해 사실을 바꾸거나 새 수치를 만들지 않는다.

## Document prose mode

1. 문장마다 같은 길이와 리듬을 반복하지 않는다.
2. `혁신적인`, `차별화된`, `효율적인`, `극대화`, `고도화`, `시너지`처럼 근거 없이 붙은 수식어를 지운다.
3. `~할 수 있습니다`, `~을 통해`, `~에 대한`, `매우`, `다양한`이 연속되면 구체적 동작과 결과로 바꾼다.
4. `또한`, `따라서`, `한편`을 기계적으로 문장마다 붙이지 않는다.
5. 명사만 나열하지 말고 주체와 동작을 드러낸다.
6. 제목은 결론을 먼저 말하고, 본문은 한 문단에 한 주장만 둔다.
7. 발표 대본은 화면 문구를 그대로 읽지 않는다. 화면이 보여 주는 사실과 청중이 내려야 할 판단을 연결한다.
8. 예상 Q&A는 모르는 내용을 아는 척하지 않고 확인 범위와 후속 검증을 분리한다.

## 금지

- 사용자가 승인한 사실·수치·URL·명령·고유명사 수정
- 확인되지 않은 성과·고객반응·시장규모 추가
- 슬라이드마다 같은 `문제 → 해결 → 기대효과` 문장틀 복제
- 빈 칭찬, 과장된 마무리, AI 자기소개, 메타 설명
- 복사용 프롬프트와 코드 블록의 자연어 재작성

## 두 번의 gate

1. `content_report` 확정 뒤, `slide_blueprint`와 실제 슬라이드 문구를 만들기 전에 윤문한다.
2. 발표 대본과 예상 Q&A 작성 뒤 다시 윤문한다.

`kill-ai-slop`이 있으면 Document prose mode를 사용하고 `humanize-korean` 위임 결과를 받는다. 없으면 위 규칙을 직접 적용한다. 완료 기록에는 적용 파일, 보호 문자열 수, 보호값 대조 결과, 사용 방법을 남긴다.
