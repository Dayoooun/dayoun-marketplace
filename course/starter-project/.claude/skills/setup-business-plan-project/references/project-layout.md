# 범용 프로젝트 구조

```text
사업계획서_프로젝트/
├─ 00. 시작하기/
├─ 01. 사업정보/
│  └─ 공유가능 원본/
├─ 02. 목적 및 요구사항/
│  └─ 원본/
├─ 03. 사업계획서양식/
│  ├─ 원본/
│  └─ 작업용 HWPX/
├─ 04. 조사자료/
│  └─ 출처원문/
├─ 05. 작성초안/
├─ 06. 검토결과/
├─ 07. 최종본/
├─ 08. 발표덱/
└─ 99. 원본백업/
```

## 운영 규칙

- 지원사업 공고가 없으면 `02. 목적 및 요구사항`에 독자, 의사결정, 필수 장·절을 기록한다.
- 양식이 없으면 `03. 사업계획서양식`을 비워 두고 Markdown 초안부터 작성한다.
- 내가 알고 있는 정보, 외부 확인이 필요한 내용, 앞으로 할 계획을 구분한다.
- 원본은 원본 폴더와 백업에 보관하고 직접 수정하지 않는다.
- AI가 만든 문안은 `05. 작성초안`, 검토 결과는 `06. 검토결과`, 승인된 결과만 `07. 최종본`에 둔다.
- 파일명은 `YYYYMMDD_문서명_v01` 형식을 권장한다.

## 10단계와 폴더 연결

| 단계 | 기본 산출 폴더 |
|---:|---|
| 1. 공고·평가지표·지침·양식 분석 | `02. 목적 및 요구사항`, `03. 사업계획서양식` |
| 2. 회사·사업·아이디어 분석 | `01. 사업정보` |
| 3. 근거와 확인 질문 도출 | `02. 목적 및 요구사항`, `04. 조사자료` |
| 4. 시장·고객·경쟁·가격·규제 조사 | `04. 조사자료` |
| 5. 전략·실행·수익구조 설계 | `05. 작성초안` |
| 6. 평가·양식 맞춤 텍스트 초안 | `05. 작성초안` |
| 7. 검토·수정·사용자 승인 | `06. 검토결과` |
| 8. 승인 내용 HWPX 반영 | `03. 사업계획서양식/작업용 HWPX`, `07. 최종본` |
| 9. HWPX 구조·화면검사 | `06. 검토결과`, `07. 최종본` |
| 10. PPT·대본·예상 Q&A | `08. 발표덱` |

모든 단계는 `00. 시작하기/단계상태.json`에 순서·상태·evidence를 남긴다.
참고 자료가 있는 외부 폴더는 읽기 전용이며 프로젝트 안에서 파일을 만들지 않는다.
`DEMO`에서는 확인된 자료와 가정으로 자동 검증하되 승인·인터뷰·견적을 합성하지 않는다. `REAL`에서는 `사용자협업상태.json`의 확인 질문·전략·승인·선택 기록이 없으면 해당 단계가 BLOCK된다.
최상위 디렉터리는 위 10개와 `.agents`, `.claude`, `.dayoun`, `.git`만 허용한다.
단계 evidence는 그 단계 산출 폴더의 새 파일이어야 하며 디렉터리·다른 단계·재사용 파일은 BLOCK한다.
DEMO/PARTIAL은 7단계를 BLOCK으로 기록하고 8~10단계를 승인·선택한 것으로 만들지 않는다.
