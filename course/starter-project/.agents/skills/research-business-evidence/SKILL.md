# 사업계획서 근거 조사

## 입력

- 사업계획서의 목적과 독자
- 확인할 문장 또는 질문
- 사용자가 제공한 사업 정보와 기존 자료
- 공식 공고·평가표가 있다면 해당 원문
- 사용자가 확인한 `04. 조사자료/방향결정.md`
- 평가항목별 `04. 조사자료/조사질문.md`

## 파이프라인 위치: 3단계 방향 인터뷰·질문을 받아 4단계 독립 근거 조사

포괄적인 시장조사부터 시작하지 않는다. 공고 요구사항·평가지표·사업정보를 비교하고 사용자가
확인한 `04. 조사자료/방향결정.md`를 먼저 읽는다. 방향 확인 기록이 없으면 외부 조사 worker를
시작하지 않고 BLOCK한다. `근거공백표`와 `04. 조사자료/조사질문.md`의 각 질문에는 어떤
평가항목, 핵심 가정 또는 작성 항목을 판단하기 위한 조사인지 기록한다.

**완료 조건**: FULL과 교육 실습은 서로 겹치지 않는 의미 있는 조사 lane 3개 이상을 만들고
worker 3개 이상을 각각 독립 실행한다. 각 worker 결과에는 확인 내용·출처·기준일·단위·한계,
성공·실패 상태와 `유지 / 수정 / 보류` 판정이 있어야 한다. worker 결과를 섞기 전에
`04. 조사자료/독립조사/worker-01.md`처럼 별도 파일로 저장하고,
`04. 조사자료/독립조사종합.md`에서 충돌·공통점·미확인 항목을 합친다. 의미 있는 질문이
3개보다 적으면 억지 질문을 만들지 말고 사유를 기록해 BLOCK한다. 근거가 사업의 핵심 가정을
부정하면 초안으로 넘어가지 않고 회사·아이디어 분석과 전략 설계 단계로 되돌린다.

**다음 단계**: 조사 결과를 `complete-business-plan` 5단계 전략 설계와
`draft-business-plan` 6단계 텍스트 초안의 근거로 넘긴다.

## 조사 절차

1. `방향결정.md`의 고객·문제·첫 제품 또는 서비스·판매 방식·조사 우선순위를 확인한다.
2. 조사 질문을 서로 겹치지 않는 lane으로 나눈다. 기본 후보는 `시장·고객·정책`, `경쟁대안·가격`, `기술·원료·비용·규제`이며 사업에 맞지 않는 후보는 다른 근거 공백으로 바꾼다.
3. FULL과 교육 실습은 `독립조사계획.json`에 lane·질문·허용 출처 범위·worker·상태를 기록하고 worker 3개 이상을 각각 시작한다. 한 worker의 중간 결과를 다른 worker 입력으로 넘기지 않는다.
4. worker마다 공식 통계, 정부·공공기관, 법령 원문, 기업 공시, 학술 원문, 제품 공식 페이지 같은 1차 자료를 우선한다.
5. 고객 인터뷰·관찰·문의 기록은 시장 통계와 구분해 고객 근거로 기록한다.
6. 검색 결과 제목이나 AI 요약만 근거로 쓰지 않고 원문을 연다.
7. 각 자료에 출처, 작성 기관, 발표일, 기준연도, 단위, 확인일, 적용 범위를 기록한다.
8. 확인한 외부 근거는 `E001`부터, 사용자 제공 사실은 `U001`부터, 검증가설은 `H001`부터, 앞으로 할 실행계획은 `P001`부터 중복 없이 부여하고 `00. 시작하기/근거목록.csv`에 등록한다.
9. 자료가 직접 답하지 못하는 부분과 해석의 한계를 함께 적는다.
10. 서로 충돌하는 수치가 있으면 정의, 지역, 기간, 표본, 단위 차이를 비교하고 하나를 임의로 고르지 않는다.
11. worker가 실패하거나 시간·사용량 한도에 도달하면 실패 사유와 미확인 질문을 남긴다. 성공한 worker만으로 전체 조사 완료를 선언하지 않는다.
12. worker별 원문 결과를 저장한 뒤에만 `독립조사종합.md`에서 공통점·충돌·한계를 비교한다.
13. 조사 결과가 기존 문장을 유지·수정·보류 중 무엇으로 바꾸는지 기록한다.
14. 초안의 모든 주장 문단 끝에는 `[E001 | 기관명, {발표연도}]`, `[U001 | 사용자 제공자료, {기록연도}]`, `[H001 | 검증가설]`, `[P001 | 실행계획]` 중 해당 표지를 붙인다. 최종 HWPX에는 내부 ID 대신 `(기관명, 연도)` 형식이 보인다.
15. 개인정보와 비공개 고객 기록은 익명화한다.

웹 도구를 사용할 수 없으면 제공된 오프라인 자료만으로 같은 형식을 연습하고, 최신 조사 완료라고 말하지 않는다.

## 결과물

`04. 조사자료`에 다음을 저장한다.

- `방향결정.md`: 조사 전에 사용자가 확인한 고객·문제·제품·판매 방식·우선순위
- `조사질문.md`: 평가항목·핵심 가정과 연결된 조사 질문
- `독립조사계획.json`: lane·질문·worker·허용 출처·시작·완료·실패 상태
- `독립조사/worker-01.md` 이후: worker별 원문 결과, 출처·날짜·단위·한계·상태
- `독립조사종합.md`: 공통점·충돌·미확인 항목·유지/수정/보류
- `조사기록.md`: 질문, 확인 내용, 출처, 날짜, 단위, 한계, 다음 확인
- `시장조사.md`: 시장·고객·가격·비용 관련 핵심 결과
- `경쟁대안비교.csv`: 같은 고객과 사용 상황을 기준으로 비교
- `출처원문/`: 공개 가능하고 저장이 허용된 원문 또는 링크 메모

근거가 없으면 문장을 꾸며 채우지 말고 `{확인필요: 내용}`으로 남긴다. 자세한 출처 선택 기준은 `references/source-policy.md`를 읽는다.
