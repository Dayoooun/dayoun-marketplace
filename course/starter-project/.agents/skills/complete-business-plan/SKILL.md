# 사업계획서 처음부터 끝까지

사용자가 가진 자료와 공식 기준을 먼저 잠근 뒤 필요한 만큼만 진행한다. 특정 기관의
기준을 기본값으로 가정하지 않고, 사용자가 제공한 최신 공식 원문을 최우선으로 삼는다.

## 먼저 공식 입력을 잠근다

공고문·평가지표·작성지침·사업계획서 양식·FAQ·수정공고가 있으면 먼저 목록을 만들고
서로 다른 버전과 날짜를 확인한다. 공식 자료에 있는 내용을 사용자에게 다시 묻지 않는다.

## 핵심 정보가 비어 있으면 하나만 묻기

공식 입력과 기존 자료를 확인한 뒤에도 사업 아이디어의 **고객·사용 상황·문제**가
비어 있으면 다음 질문 하나만 하고 답을 기다린다.

> 누가, 어떤 상황에서, 어떤 문제를 해결하기 위해 이 사업을 이용하나요? 아직 모르면 모른다고 적어 주세요.

사용자가 이미 말한 내용은 다시 묻지 않는다.

## 지원하는 작업

- 새로 작성: 아이디어와 자료에서 사업계획서의 뼈대와 초안을 만든다.
- 기존 문서 보완: 현재 문서에서 빠졌거나 약한 내용을 찾아 고친다.
- 공고·평가기준 맞춤: 사용자가 제공한 최신 공식 공고, 평가표, 양식을 우선 적용한다.
- 자율 사업계획: 공고가 없으면 독자, 의사결정 목적, 필요한 장·절을 먼저 정한다.

지원사업 신청, 투자·IR, 사내 검토, 대출·제안, 교육 실습 등 용도를 구분한다. 특정 기관의 기준을 기본값으로 가정하지 않는다.

## 1단계 공고·평가지표·지침·양식 분석 계약

지원사업·공모 작업은 초안보다 아래 분석을 먼저 끝낸다.

| 확인 항목 | 기록할 내용 |
|---|---|
| 자격 | 신청 자격, 제외 대상, 지역·업력·업종 조건 |
| 지원 | 지원금, 자부담, 지원 비율, 협약 기간 |
| 일정 | 접수 시작·마감 시각, 평가·발표·협약 일정 |
| 제출 | 제출서류, 파일 형식, 제출 채널, 서명·날인 |
| 평가 | 평가 단계, 항목, 공식 배점, 가점·감점 |
| 작성 | 장·절 질문, 페이지·글자 수, 표·첨부 제한 |
| 변경 | 수정공고·FAQ가 원공고를 바꾼 내용 |
| 근거 | 항목별 원문 파일, 페이지·절, 기준일 |
| 연결 | 공고 요구사항 → 초안 장·절 → 근거 위치 |

산출물은 `공고분석표`, `요구사항-양식-평가지표 연결표`, `확인필요목록`이다.
원문에서 확인되지 않은 값은 추정하지 않고 `확인 필요`로 둔다.

## 처음부터 발표까지 10단계

1. **공고문·평가지표·작성지침·사업계획서 양식 분석**: 위 분석 계약에 따라 공식 요구와 양식 위치를 연결한다.
2. **회사·사업 현황·아이디어 분석**: `setup-business-plan-project`로 원본을 보존하고 사실·미확인 정보·가정·계획을 나눈다.
3. **부족한 근거와 확인 질문 도출**: 평가항목별 현재 답변, 부족한 근거, 조사 질문을 만든다.
4. **시장·고객·경쟁·가격·규제 조사**: `research-business-evidence`로 3단계 질문에 필요한 근거만 조사한다.
5. **사업전략·실행계획·수익구조 설계**: 문제·고객·해결책·차별점·시장·수익·실행·팀·재무·위험을 연결한다.
6. **평가지표와 양식에 맞춰 텍스트 초안 작성**: `draft-business-plan`으로 HWPX가 아닌 검토 가능한 텍스트 초안을 먼저 만든다. 시각자료가 판단에 도움이 되면 종류·핵심 메시지·근거·표 셀·앞 문단·뒤 문단·짧은 캡션을 함께 설계한다.
7. **검토·수정·사용자 승인**: `review-business-plan`으로 BLOCK을 처리하고 최종 표현과 공개 범위를 승인받는다.
8. **선택한 경우 승인 내용을 HWPX 양식에 반영**: HWPX를 요청했을 때만 수정 가능한 복사본에 `fill-hwpx-template`을 사용한다. 시각자료는 답변 셀 마지막이 아니라 명세한 설명 문단 직후에 배치한다.
9. **선택한 HWPX 구조·화면검사**: HWPX를 요청했을 때만 ZIP/XML 구조·미치환 항목과 표·줄바꿈·페이지 넘김을 검사한다.
10. **선택한 PPT·대본·예상 Q&A 제작**: PPT를 요청했을 때 `ppt-editorial`이 승인 canonical을 발표용 메시지로 재구성한다. HWPX 입력이나 검증 기록은 요구하지 않는다.

### 10단계 순차 실행 강제

작업을 시작하기 전에 `../setup-business-plan-project/scripts/create_project.py`로
`00. 시작하기`부터 `99. 원본백업`까지 강제 구조를 만든다. 입력 참고 폴더에는
파일이나 폴더를 새로 만들지 않는다.

각 단계는 `../setup-business-plan-project/scripts/advance_stage.py`의 `start`로 시작하고,
해당 번호 폴더에 산출물을 저장한 뒤 실제 파일 경로를 evidence로 `complete`한다.
1~7단계는 PASS 없이 건너뛸 수 없다. 8~10단계는 선택하지 않았을 때만
NOT_REQUESTED로 기록한다. BLOCK인 단계가 있으면 다음 단계의 작성·HWPX·PPT를
시작하지 않는다.

`DEMO`는 자동 회귀검증·강의시연에만 쓴다. `REAL`에서는 질문·대안을 먼저 제시하고
사용자 답을 `00. 시작하기/사용자협업상태.json`에 기록하면서 함께 범위를 좁힌다.
특히 3단계 질문 확인, 5단계 전략 선택, 7단계 문안 승인, 8단계 HWPX 선택,
10단계 발표자료 선택을 에이전트가 대신 결정하지 않는다. 외부 조사와 문서 분석은
답을 기다리는 동안 병렬로 진행할 수 있지만 사용자 선택이 필요한 값을 확정하지 않는다.

### 시각자료 기본값

시각자료를 선택하면 `../fill-hwpx-template/references/visual-design-system.md`를 따른다.
답변 셀 마지막 일괄 배치는 금지하고 `앞 문단 / 뒤 문단`으로 의미상 위치를 고정한다.
별도 디자인 요구가 없을 때만 Pretendard와 밝고 절제된 정보 디자인을 기본으로 사용한다.
공식 양식, 사용자 요구, 브랜드 기준이 이 기본값보다 우선하며 원본 쪽 여백은 바꾸지 않는다.

### 단계 게이트

- 1단계 공식 기준과 2단계 사업정보를 확인하기 전에는 시장조사 범위를 확정하지 않는다.
- 3단계 질문 없이 포괄적인 시장조사를 시작하지 않는다.
- 4단계 근거가 핵심 가정을 부정하면 2·3·5단계로 돌아가 계획을 고친다.
- 5단계 전략 연결이 끝나기 전에는 실제 사업계획서 초안을 쓰지 않는다.
- 7단계 승인 전에는 선택한 HWPX·PPT를 생성하지 않는다.
- HWPX를 선택했다면 자동 구조검사와 한글 외부 화면검사가 모두 PASS하기 전에는 HWPX 완료라고 말하지 않는다.
- PPT를 선택했다면 mode 자동검사·fact/structure/contract 검증자 전원 PASS·PPTX/PDF 외부 화면검사가 모두 PASS하기 전에는 PPT 완료라고 말하지 않는다.
- 플러그인에서는 `validators/`, course starter에서는 `.dayoun/validators/`의 fact·structure·contract 스크립트를 각각 실행하고 `aggregate_validators.py`로 합친다. 한 검증자의 PASS나 사람의 판단이 다른 BLOCK을 덮지 않는다.

## 정보 구분

- **내가 알고 있는 정보**: 사용자가 제공한 회사, 팀, 제품, 고객, 실적 정보다. 출처나 확인 상태를 함께 적는다.
- **확인이 필요한 내용**: 시장 규모, 고객 반응, 경쟁 비교처럼 조사나 고객 기록으로 확인해야 할 내용이다.
- **앞으로 할 계획**: 아직 일어나지 않은 일정, 매출, 채용, 개발 계획이다. 현재 실적처럼 쓰지 않는다.

내부 파일에서는 추적을 위해 번호를 붙일 수 있지만, 초보자 안내에는 번호보다 위의 쉬운 이름을 사용한다.

## 완료 기준

작업 시작 시 아래 중 범위를 선언하고, 범위 밖은 완료로 표시하지 않는다.

- QUICK: 가장 중요한 보완점 1개와 근거 1개, 수정안 1개, 다음 행동 1개
- SECTION: 사용자가 선택한 장·절 전체
- FULL: 목적에 필요한 전체 문서와 필수 요구사항

항상 다음을 지킨다.

- 사용자가 주지 않은 실적, 수치, 고객 반응, 계약, 인증을 만들지 않는다.
- 공식 배점이나 요구사항이 없으면 임의 기준을 공식 기준처럼 말하지 않는다.
- 출처의 발표일, 기준연도, 단위, 적용 범위를 함께 기록한다.
- 원본은 보존하고 초안과 최종본을 구분한다.
- 개인정보와 비공개 자료는 제거하거나 가린다.
- 선택하지 않은 HWPX·PPT는 `NOT_REQUESTED`로 기록하고 PASS로 세지 않는다.
- 선택한 HWPX는 구조검사와 한글 화면 확인을, 선택한 PPT는 승인 tuple 대조·mode 자동검사·세 검증자·외부 화면검사를 모두 통과해야 한다.

세부 단계와 산출물은 `references/workflow.md`를 읽는다.
